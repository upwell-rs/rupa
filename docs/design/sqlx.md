# sqlx drivers

Status: **implemented** (2026-10-17). Milestone 11's sqlx item:
`rupa-driver-sqlx`, async Postgres, MySQL and SQLite on sqlx 0.9.

## Shape

One generic executor, pool and registry driver, instantiated per database:

| facade feature | crate feature | `Backend` | registry name | aliases module |
|---|---|---|---|---|
| `sqlx-postgres` | `postgres` | `sqlx::Postgres` | `sqlx-postgres` | `rupa_driver_sqlx::postgres` |
| `sqlx-mysql` | `mysql` | `sqlx::MySql` | `sqlx-mysql` | `rupa_driver_sqlx::mysql` |
| `sqlx-sqlite` | `sqlite` | `sqlx::Sqlite` | `sqlx-sqlite` | `rupa_driver_sqlx::sqlite` |

- `SqlxExecutor<DB>` owns one sqlx connection; it is an `AsyncExecutor`
  and `AsyncTxConnection`, so transactions, savepoints and deferred
  rollbacks work as in the tokio-postgres driver.
- `Backend` (sealed) is the per-database glue: binding `Value`s, reading
  columns, and the three I/O calls (`execute`, `fetch`, `script`). The I/O
  calls are the same code for each database, generated by a macro, because
  sqlx's executor bounds (`&mut DB::Connection: Executor`) can only be
  named per database. Writing them as generic higher-ranked bounds would
  have to be repeated on every generic impl.
- The modules define short aliases: `postgres::{PgExecutor, PgPool,
  PgDriver, ..}` and the same for the other two.

## Decisions

- **deadpool, not sqlx's pool.** A pooled rupa connection carries the
  rollback a dropped transaction still owes. sqlx's pool can't hold that
  state, and doesn't know about transactions rupa opened with plain SQL.
  deadpool owns `SqlxExecutor`s, cleans them on recycle, and takes the same
  `PoolConfig` as every other driver. Connections whose statement failed
  with an I/O, TLS or protocol error are marked broken and discarded.
- **Transaction control is rupa's**, rendered by `rupa-sql` and sent with
  `raw_sql`. sqlx's `Transaction` isn't used, so isolation levels,
  read-only and savepoints behave exactly as in the other drivers.
- **Prepared statements are sqlx's**: its per-connection LRU, keyed by SQL
  text. `statement_cache_size` sets its capacity (sqlx's default is 100).
  SQL is passed as the render cache's `Arc<str>` (`AssertSqlSafe`, since
  rupa always binds values), so it isn't copied.
- **Values are stored as the other drivers store them**, so a database
  written by one driver reads the same in another:
  - **MySQL:** UUIDs and JSON as text; `DateTime<Utc>` as a UTC
    `DATETIME(6)`.
  - **SQLite:** rusqlite's text formats for dates and times.
  - **Postgres:** values are bound with their own types, and Postgres casts
    them where needed.
  - **Reading:** columns are decoded by their type, with the same widening
    and narrowing rules as the other drivers. MySQL's `DECIMAL` (e.g.
    `SUM`) is read as digits.
- **MySQL semantics:** sqlx sets `CLIENT_FOUND_ROWS` and a UTC session time
  zone itself.
- **SQLite URLs** are parsed by `rupa_core::config::SqliteTarget`, moved out
  of the rusqlite driver so both read URLs the same way. An in-memory
  database gets a single connection.
- **rusqlite 0.39, not 0.40.** sqlx 0.9's SQLite needs
  `libsqlite3-sys < 0.38`, and a build can link only one SQLite. Move back
  to 0.40 when sqlx catches up.

## Registry order and fallback

The facade registers drivers in this order:

1. `postgres`
2. `sqlx-postgres`
3. `postgres-sync`
4. `sqlite`
5. `sqlx-sqlite`
6. `mysql`
7. `sqlx-mysql`
8. `memory`

For each database, the driver named after it comes first. That keeps
`driver = "sqlite"` and a bare `sqlite:` URL resolving to the same driver.
On Postgres, async drivers come before the sync one.

`Registry::resolve` gained one rule: if the named driver isn't registered
but the name is one rupa knows, the first registered driver for the same
database (`DriverConfig::dialect`) and URL scheme serves it. Without it, a
build with only `sqlx-sqlite` would reject `driver = "sqlite"`, and even a
config whose driver was inferred from its options. A third-party name
(`DriverConfig::Other`) is still strict.

## Tests

- The full conformance suite, on one executor and through a pooled
  `Database`:
  - SQLite in memory;
  - Postgres and MySQL in Docker (testcontainers).
- Dirty connections are cleaned on return.
- `statement_cache_size` bounds sqlx's cache.
- Registry selection, including the fallback rule.

## Not done

- **Wrapping an existing `sqlx::Pool`.** Its connections can't carry rupa's
  per-connection state; use `SqlxExecutor::new` on a detached connection
  instead.
- **TLS options in `DbConfig`.** Configure TLS in the URL, with the
  `sqlx-tls-*` features.
